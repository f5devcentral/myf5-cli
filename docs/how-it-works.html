How myf5-cli Works

A single memory-safe, statically compiled Go binary (CGO_ENABLED=0, zero external runtime dependencies) bridging your local workstation to MyF5 Cloud APIs, iHealth Diagnostics, and BIG-IP TMOS and BIG-IQ Centralized Management appliances.

☁️

1. MyF5 Cloud APIs

Authenticates via OAuth 2.0 client_credentials (defaulting to Auth0 https://idp.identity.f5.com/oauth/token, or Okta CIAM https://identity.account.f5.com/oauth2/ausp95yxb4ShxMGvW357/v1/token when F5_AUTH_FQDN targets account.f5.com) using F5_CLIENT_ID / F5_CLIENT_SECRET (audience=api://ciam-api-myf5, scope=myf5_scope) plus ?k=<F5_API_KEY> for support.apis.f5.com (and automatic Downloads gateway fallback). Streams multi-GB ISOs, hotfixes, and GeoIP databases from regional AWS CloudFront (*.cloudfront.net) presigned URLs via io.TeeReader into .part files with single-pass SHA-256 verification and atomic os.Rename.

pkg/auth pkg/downloads pkg/cases io.TeeReader
⚡

2. BIG-IP & BIG-IQ

Direct wire-speed orchestration across BIG-IP TMOS and BIG-IQ Centralized Management. Supports BIG-IQ token login + 5-min /mgmt/shared/authn/exchange refresh, device-info discovery, direct ISO uploads, and automatic REST-to-SCP failover with SSH known_hosts verification.

pkg/bigip/failover.go Token + Exchange SSH known_hosts
🩺

3. iHealth Diagnostics

Authenticates with dedicated IHEALTH_CLIENT_ID / IHEALTH_CLIENT_SECRET (audience=api://ciam-api-ihealth, empty scope="" per K000130498). Streams .qkview archives (POST /qkview-analyzer/api/qkviews), lists uploaded QKViews (GET /qkview-analyzer/api/qkviews), and retrieves upload metadata, processing status (COMPLETE / IN_PROGRESS), linked case numbers, and direct iHealth analyzer GUI URLs (GET /qkview-analyzer/api/qkviews/{id}).

pkg/ihealth cmd/myf5/main.go IHEALTH_CLIENT_ID

Dual-Protocol Resilience

Appliance Dual Transfer & Failover Engine

How myf5-cli guarantees high-speed file transfer to BIG-IP/BIG-IQ appliances even when corporate firewalls, reverse proxies, or restricted shells block standard protocols.

Transport 1: HTTPS Port 443

iControl REST Chunked Transfer

Default method when password or mTLS authentication is available. Operates seamlessly across BIG-IP and BIG-IQ through corporate HTTPS reverse proxies and cloud access topologies.

  • BIG-IP & BIG-IQ Token Auth: Acquires X-F5-Auth-Token via /mgmt/shared/authn/login (omitting loginProviderName for BIG-IQ local auth), refreshes 5-min tokens via /mgmt/shared/authn/exchange, and prevents account lockouts on 401.
  • Platform-Specific Upload Order (512 KiB Chunks): Streams 512 KiB (DefaultUploadChunkSize) Content-Range chunks. BIG-IQ uses /mgmt/cm/autodeploy/software-image-uploads/ first for /shared/images, whereas BIG-IP stages to /mgmt/shared/file-transfer/uploads/ (/var/config/rest/downloads/) + /mgmt/tm/util/bash cp -f and falls back to software-image-uploads for .iso files if bash is disabled.
  • Discovery & Promotion: Queries /mgmt/tm/sys/* with BIG-IQ fallbacks to device-info & cm-shared-all-big-iqs; promotes staged BIG-IP files via /mgmt/tm/util/bash.
  • REST Range Downloads (1 MiB Chunks): Streams 1 MiB (1024 * 1024) Content-Range chunks from software-image-downloads, file-transfer/downloads (including single-response 200 OK handling on BIG-IQ), and BIG-IP qkview-downloads.
Transport 2: SSH Port 22

Native Go SCP Streaming

Direct high-speed streaming implemented in pure Go (golang.org/x/crypto/ssh). Zero external scp or ssh binaries required.

  • Host-Key Verification: Enforces strict OpenSSH known_hosts verification via --known-hosts / MYF5_SSH_KNOWN_HOSTS (and rejects ~/.ssh/known_hosts key mismatches before any credentials are transmitted).
  • Direct Streaming: Writes directly to destination directory via remote scp -t <dest> using a tuned 64 KiB buffer without secondary bash staging.
  • Authentication: Supports unencrypted SSH private keys (-i / default ~/.ssh/id_{ed25519,rsa,ecdsa}), SSH agent (SSH_AUTH_SOCK, including passphrase-protected keys loaded in agent), keyboard-interactive (PAM/TACACS+), and password.
  • BIG-IQ Restricted Paths & QKViews: Handles arbitrary filesystem paths (such as /var/tmp) and BIG-IQ QKView generation/retrieval where BIG-IQ webd restricts /mgmt/tm/util/bash.
⇄

The Automatic Failover Engine (pkg/bigip/failover.go)

When set to --method auto (the default), myf5 intelligently selects the optimal transport for BIG-IP or BIG-IQ. If port 443 is blocked, an HTTP 500 occurs, or Appliance Mode / BIG-IQ webd blocks /mgmt/tm/util/bash (HTTP 403/400), the CLI seamlessly routes or fails over to native Go SCP/SSH with host-key verification—zero manual re-runs — automatically restarting the stream over the alternate protocol.

Security Architecture

Zero-Secret Policy & Security Guardrails

How myf5 enforces strict enterprise DevSecOps standards to prevent credential leakage into process listings, audit logs, and shell histories.

1

Two-Tier Argv Sanitization (Exit Code 2 & Exit Code 1)

Global pkg/auth.CheckNoCLISecrets evaluates os.Args[1:] prior to command dispatch and blocks 22 secret flags (--password, --client-secret, --token, --api-key, --key, etc.) with Exit Code 2. Appliance flag parsers additionally trap --pass, -P, and --ssh-passphrase via rejectSecretFlag with Exit Code 1.

2

In-Memory Secret Zeroing

Credentials stored in auth.Credentials and bigip.TransferOptions maintain mutable byte slices (SecretBytes, PasswordBytes) that are explicitly overwritten with zeroes upon completion via Zero() and runtime.KeepAlive.

3

Log Scrubbing Engine

pkg/logger.ScrubSecrets sanitizes all debug and audit messages, regex-scrubbing OAuth2 Bearer tokens, HTTP Basic auth headers, JSON credential fields, and embedded URL credentials (e.g., https://user:REDACTED@host).

4

Cloud vs. Appliance TLS 1.2+, PQC & Corporate CA Trust

Cloud API clients always enforce strict TLS 1.2+ certificate verification with PQC hybrid ML-KEM (X25519MLKEM768), 256-bit AEAD ciphers, and custom corporate CA bundles (MYF5_CA_BUNDLE / SSL_CERT_FILE). Appliance REST clients default to SkipTLSVerify: true for self-signed lab/appliance certs unless MYF5_STRICT_APPLIANCE_TLS=1 is set (which enforces full CA verification including MYF5_CA_BUNDLE / SSL_CERT_FILE).

5

SSH Host-Key Verification & Lockout Guard

Strict mode (--known-hosts, --push-known-hosts, BIGIP_KNOWN_HOSTS, BIGIQ_KNOWN_HOSTS, MYF5_SSH_KNOWN_HOSTS, or MYF5_STRICT_HOST_KEY_CHECKING=1) rejects both unknown and mismatched host keys; default mode checks ~/.ssh/known_hosts when present and rejects recorded key mismatches/revocations before sending credentials while allowing unrecorded lab hosts. loginFailedErr prevents multi-endpoint 401 account lockouts on BIG-IP and BIG-IQ.

Outbound Proxy & NO_PROXY Resolution (pkg/client/proxy.go)

Supports http://, https://, socks5://, and socks5h:// (remote DNS resolution over SOCKS5). Precedence order: --proxy <url> → in-process proxy set → MYF5_PROXY → F5_PROXY → ALL_PROXY → HTTPS_PROXY → HTTP_PROXY → ~/.f5api_credentials (proxy key). NO_PROXY / no_proxy supports exact IPs, IPv6, CIDR blocks (e.g. 10.0.0.0/8), domain suffixes, and *.
