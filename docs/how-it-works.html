Appliance Dual Transfer & Failover Engine

How myf5-cli guarantees high-speed file transfer to BIG-IP/BIG-IQ appliances even when corporate firewalls, reverse proxies, or restricted shells block standard protocols.

Transport 1: HTTPS Port 443

iControl REST Chunked Transfer

Default method when password authentication is available. Operates seamlessly through corporate HTTPS reverse proxies and cloud access topologies (such as F5 UDF).

  • Chunking: Splits payloads into 512 KB sequential chunks using HTTP Content-Range headers.
  • Staging Path: Targets /mgmt/shared/file-transfer/uploads/<filename>, staging in /var/config/rest/downloads/.
  • Bash Promotion: Invokes /mgmt/tm/util/bash to copy files directly into /shared/images/ or /shared/GeoIP/.
  • QKView Download: Directly streams diagnostic bundles from /mgmt/cm/autodeploy/qkview-downloads/.
Transport 2: SSH Port 22

Native Go SCP Streaming

Direct high-speed streaming implemented in pure Go (golang.org/x/crypto/ssh). Zero external scp or ssh binaries required.

  • Direct Streaming: Writes directly to destination directory via remote scp -t <dest> without secondary bash staging.
  • Buffer Size: High-throughput 64 KB streaming buffer tuned for data center LANs and 10GbE management interfaces.
  • Authentication: Supports SSH private keys (with encrypted passphrase prompting), SSH agent (SSH_AUTH_SOCK), and password.
  • Arbitrary Paths: Pulls or pushes any file on the TMOS filesystem directly without REST endpoint restrictions.
⇄

The Automatic Failover Engine (pkg/bigip/failover.go)

When set to --method auto (the default), myf5 tries the primary transport first. If port 443 is blocked, an HTTP 500 error occurs, or the REST autodeploy endpoint is disabled, the CLI instantly traps the failure, prints a distinct yellow [FAILOVER] notice, and re-executes the transfer over native Go SCP—zero manual re-runs or lost progress.

Security Architecture

Zero-Secret Policy & Security Guardrails

How myf5 enforces strict enterprise DevSecOps standards to prevent credential leakage into process listings, audit logs, and shell histories.

1

Argv Sanitization & Exit Code 2

pkg/auth.CheckNoCLISecrets evaluates os.Args prior to command dispatch. Flags like --password, --client-secret, --token, or --key are strictly forbidden and immediately terminate with Exit Code 2.

2

In-Memory Secret Zeroing

Credentials stored in auth.Credentials and bigip.TransferOptions maintain mutable byte slices (SecretBytes, PasswordBytes) that are explicitly overwritten with zeroes upon completion via Zero() and runtime.KeepAlive.

3

Log Scrubbing Engine

pkg/logger.ScrubSecrets sanitizes all debug and audit messages, regex-scrubbing OAuth2 Bearer tokens, HTTP Basic auth headers, JSON credential fields, and embedded URL credentials (e.g., https://user:REDACTED@host).

4

Strict TLS 1.2+ & AEAD Ciphers

pkg/client.SecureTLSConfig enforces a minimum of TLS 1.2 with modern Perfect Forward Secrecy (PFS) and AEAD cipher suites (ECDHE-ECDSA/RSA with AES-GCM or ChaCha20-Poly1305). Plain unencrypted HTTP is strictly disallowed.
